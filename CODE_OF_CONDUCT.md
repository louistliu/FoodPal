## Assignment description
Our team will develop a recipe manager, focusing on teamwork, planning, and implementing core and at least two extra requirements from the assignment.
## Target or ambition level
We aim for a grade of 8, achieving all base requirements and at least two extra features.
## Planning
-   **Availability**: Team members commit to being available Monday-Friday, 9 AM - 5 PM CEST.
-   **Merge Request Deadlines**: Submission by Thursday 2 PM; feedback by Friday 1:30 PM (before TA meeting).
-   **Work Completion**: Reminders will be sent. Persistent issues may escalate to the TA by majority decision.
-   **Final Deliverable**: All team members must agree on the final product. Floyd will submit it to Brightspace.
## Communication:
-   **Mattermost**: Logistical communication, TA communication (agenda, general discussion, reminders).
-   **Gitlab**: Codebase-related communication (merge requests, issues, milestones).
## Collaboration outside of the mandatory meetings:
-   **Tuesday Meetings**: Mandatory in-person attendance. Notify 2 hours in advance for absence/online attendance. Communicate lateness ASAP.
-   **Asynchronous**: Gitlab for issues/milestones/MRs; Mattermost for continuous real-time communication.
## Helping each other:
-   Each person is responsible for their own assigned work and thus asking for help.
-   **Preferred Platform**: Mattermost or in-person (depending on the situation).
-   **Response Time**: Team members must respond to help requests within 1 day, should ask for help 1 day before the deadline at the latest.
## Work quality:
-   **AI Usage**: Must be credited and fully understood.
-   **Automated Testing**: Checkstyle must pass. Unit tests for new/modified code (at least 50% coverage); add tests for bugs.
-   **CI/CD**: Ensure code runs locally and CI/CD passes before committing/merging/pushing. Fix failures within one hour.
-   **Code Review /Approvals**: All changes require verification by other team members (creator included):
    -   All members: Core changes, Code of Conduct, Gitlab settings.
    -   At least 4 members: Breaking changes.
    -   At least 3 members: Full feature implementation
    -   At least 2 members: meeting docs (chair/minute-taker edits, merged from branch), code refactoring.
-   **Addressing Poor Quality**: Discuss with creator directly via mattermost or in MR, create Gitlab issue for fixes. Recurring issues escalate to TA  (see [[#Problem resolution]]).
## Decision-making:
Decisions combine majority vote and consensus, with work quality requirements applying.
-   **Consensus-driven**: Minor changes (Java doc, small unit tests), small feature architecture, code improvements, non-intercommunicating server/client logic, general docs.
-   **Unanimous vote**: New features expanding project scope, drastic system overhauls/tech stack changes, Gitlab settings.
## Broken agreements
Follow these steps if an agreement is broken, escalating if behavior doesn't improve:
1.  Communicate expectations directly.
2.  Discuss during a team meeting.
3.  Escalate to the TA.
## Problem resolution
-   **Disagreements**: Discuss internally in meetings. If unresolved, seek second opinions. Escalate to TA if healthy discussion ceases or mediation is needed.
-   **Lateness**: Communicate lateness ASAP. Persistent lateness will be handled as a broken agreement.
-   **Escalation to TA**: When internal resolution fails for broken agreements or significant disagreements, or for persistent non-contribution.
